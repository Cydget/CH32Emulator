## Work log

- The repository started as a README and a Rust gitignore. No emulator code was present.
- Target chosen for the first machine: CH32V203C8T6. QingKe V4B, RV32IMC, 64 KiB zero-wait flash at `0x08000000` (aliased at `0x00000000`), 20 KiB SRAM at `0x20000000`. Memory map and IRQ numbers taken from `ch32-data` (`CH32V203C8T6.yaml`, `CH32V2_V3.yaml`, `CH32V2_D6.yaml`). TIM2 is IRQ 44.
- Firmware under test uses `ch32-hal` (the Embassy HAL in the ch32-rs org, which consumes `ch32-metapac` generated from `ch32-data`) plus `embassy-executor` and `embassy-time`. The published blink example toggles a GPIO pin. This session's firmware toggles PA15 and increments the SRAM static `BLINK_COUNT`, waiting with `embassy_time::Timer`.
- QingKe startup (`qingke-rt`) copies `.data`, clears `.bss`, writes CSRs `0x800` (gintenr), `0x804` (intsyscr), `0xBC0` (corecfgr), sets `mtvec` to vectored-address mode, and `mret`s into `main`. Interrupt handlers assume the hardware stack pushes caller-saved registers. `mtvec` mode 3 loads the handler address from the vector table.
- The host Rust toolchain and a C linker were not installed. Rust 1.99 and `build-essential` were installed, plus the `riscv32imc-unknown-none-elf` target.
- `qingke` 0.8 refuses to build on this target unless `unsafe-trust-wch-atomics` is enabled, because the target reports byte atomics. The firmware enables that feature.
- Embassy's RISC-V thread executor runs `wfi` inside a critical section. QingKe critical sections clear both MIE and MPIE. The emulator keeps a trap-entry stack of the previous global-enable bit so `mret` still restores it. Without that, the first timer interrupt left the core with interrupts stuck off.
- A headless run of the release ELF for 2,000,000 instructions finished with no faults, PA15 configured as push-pull output, and `BLINK_COUNT` at 5. The web server served the UI and a WebSocket client loaded the same ELF, started the core, and observed `BLINK_COUNT` and PA15.

## Work log

- The web UI gained a peripheral inspector under the pin, core, and variable panels. Two menus select the block and the instance (TIM, then TIM2, and the same for GPIOA–D, RCC, SysTick, USART1, and the PFIC).
- The selected peripheral lists the inputs it is sampling (for TIM2: clock enable, CEN, URS, PSC, the internal prescaler count, ATRLR, CNT, DMAINTENR, INTFR, and the capture registers) and the changes its next update will make. A register change includes the guest address, the old value, and the new value. A TIM2 counter reset names `CNT` at `0x40000024`. The prescaler count is shown too, marked as internal because it is not memory-mapped. The prediction is the peripheral's own tick, not stores performed by the instruction about to execute. PFIC pending bits that follow an IRQ-line change are described as latching at the start of the next step, which is when the model writes them.
- Unlimited speed had been sharing the idle path's 20 ms pause, so it was capped near 100 kHz. It now runs for about 12 ms, yields for 2 ms so the page can refresh, and the speed control shows the measured guest rate (for example "running at 2.45 MHz") while that option is selected. A finite speed still paces to the chosen rate and does not show a measured number.
- Checked with `cargo test -p ch32-emu` (the new test sets TIM2 up to reload and checks the CNT address, old value 4, and new value 0, then steps once and sees the counter actually clear). A WebSocket client against the debug server confirmed the page markup, the TIM2 input address, and an unlimited run reporting about 2.45 MHz. No browser was available, so the menus were not clicked by hand.

## Work log

- Static variables gained a break control: pick a symbol, then Off, Increments, Decrements, or Equals plus a number. Step with a break armed runs until that transition (capped at 2,000,000 instructions). Run stops on the same condition.
- Back reverses one instruction. The machine keeps the last 10 cycles as a small undo record (register file, peripheral registers, and the bytes each instruction wrote) rather than a full memory copy, so running stays usable. A pin drive applied after an instruction is left in place when you reverse past it.
- Tests cover each break condition, a step that stops when a static increments, decrements, or reaches a value, and reverse of a store plus the 10-cycle limit. No browser was available, so the new controls were not clicked by hand.
